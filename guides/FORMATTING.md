# 코드·그림 표준

현재 공개 글과 `docs/stylesheets/fieldnotes.css`를 기준으로 한 공통 형식. 글마다 새 CSS나 디자인을 만들지 않고 아래 예제를 재사용. [복사할 예제](../templates/formatting.md) · [SVG 원본](../templates/assets/diagram.svg).

홈의 `figure_lines`는 대표 글의 짧은 시각 요약. 본문의 설명용 그림은 아래 양식을 사용.

## 코드박스

Markdown 코드 펜스 사용. 사이트에서 JetBrains Mono, 밝은 회색 배경, 얇은 테두리, 복사 버튼 적용. 긴 줄은 코드박스 안에서 가로 스크롤. 본문에 별도 `<pre>`나 검은 박스 스타일을 추가하지 않음.

| 내용 | 언어 표시 | 작성 방식 |
| --- | --- | --- |
| 실행 명령 | `bash` | 복사할 명령만. `$`, `#`, `root@host` 프롬프트 제외 |
| 로그·명령 출력 | `text` | 명령과 분리. 실제 출력·예상 출력 예시 여부 표시 |
| 설정 파일 | `yaml`, `json`, `ini`, `toml` | 파일 경로와 변경할 부분 표시 |
| 프로그램 | `python`, `javascript` 등 | 실제 언어와 파일명 표시 |
| 변경 비교 | `diff` | 변경 전·후 비교용. 실행할 코드처럼 안내하지 않음 |

- 짧은 명령·경로·옵션은 인라인 코드. 실행 절차는 코드박스.
- 박스 바로 앞에 목적과 필요한 실행 위치·대상·교체 값을 설명. 짧은 조회마다 형식적인 안내 항목을 모두 붙일 필요 없음.
- 명령 → 출력 → 해석 순서. 여러 작업과 긴 로그를 한 박스에 섞지 않음.
- 출력은 판단에 필요한 부분만 발췌. 생략한 부분은 표시. 실제 줄 번호가 아닌 번호를 임의로 붙이지 않음.
- 기본은 언어만 지정. 파일을 구분해야 하면 `title="파일명"`, 특정 줄 설명이 필요하면 `linenums="1"` 또는 `hl_lines="2"`를 선택적으로 사용. 생성된 줄 번호는 원본 파일의 줄 번호와 구분.
- 재시작·삭제 같은 조치는 영향·복구 설명을 명령 앞에 배치. 출력 예시는 실행한 증거처럼 쓰지 않음.

제목·줄 강조 구문은 [Material 코드블록 문서](https://squidfunk.github.io/mkdocs-material/reference/code-blocks/) 참고. 실제 지원 범위는 저장소의 `mkdocs.yml`과 빌드 결과로 확인.

## 그림 선택

| 설명할 내용 | 기본 형식 |
| --- | --- |
| 2~4단계의 단순한 순서 | 기존 `<figure class="flow">` 양식 |
| 분기·양방향 통신·여러 구성 요소 | `docs/assets/<글-slug>/`의 SVG |
| 설정값·변경 전후 수치 비교 | Markdown 표. 관계 설명이 없으면 그림을 만들지 않음 |
| 실제 화면 증적 | PNG 등 원본 비율 유지. 민감정보 제거 후 삽입 |

### 단순 흐름도

[기존 OVN 글](../docs/design/2026-10-06-sample-ovn-roles.md)의 양식 사용. `ol`에는 짧은 단계명, `ul`에는 순서의 의미와 범위. 아래쪽 설명이 캡션 역할.

- 한 노드에는 짧은 역할 하나. 장문의 설명·여러 줄 코드는 본문으로 이동.
- 화살표는 선행 단계에서 다음 단계로 이어지는 순서. 응답 경로나 병렬 분기를 이 양식으로 표현하지 않음.
- 데스크톱은 가로, 모바일은 세로 배치. HTML 구조와 `flow` 클래스 유지.
- 한 그림이 복잡해지면 분리하거나 SVG 선택. 임의 인라인 스타일 추가 없음.

### 구성도·분기 그림

[SVG 템플릿](../templates/assets/diagram.svg)을 복사해 구성 요소와 연결 수정. 수정 가능한 SVG를 원본으로 보관. Mermaid로 생성하는 경우에도 소스 `.mmd`와 렌더링한 `.svg`를 함께 보관하고 본문에는 SVG를 연결.

현재 사이트에는 Mermaid 런타임 설정이 없으므로 `mermaid` 코드 펜스만 작성하고 그림이 표시된다고 가정하지 않음. 설정을 추가하려면 별도 사이트 변경 요청으로 처리. [Material 다이어그램 설정](https://squidfunk.github.io/mkdocs-material/reference/diagrams/) 참고.

| 요소 | 기준 |
| --- | --- |
| 본문·노드 글자 | `#1e293b`, Pretendard 계열과 시스템 한글 글꼴 대체 |
| 노드 배경·윤곽 | 흰색, 남색 `#0b1f3a` 얇은 선 |
| 그림 배경 | 흰색 또는 옅은 파랑 `#eff5ff` |
| 기본 연결선 | 파랑 `#2563eb`, 방향을 나타내는 화살표 |
| 보조 설명 | `#3d4d63` |
| 문제 지점 | 필요한 경우에만 주황 `#f97316`, “지연” 등 텍스트도 표시 |

- `viewBox`와 여백을 유지해 크기 조절 시 잘리지 않도록 작성.
- 글자·화살표·노드 겹침 없이 배치. 글꼴은 SVG의 표시 환경에서 대체될 수 있으므로 실제 화면에서 확인.
- 실선은 기본 경로. 점선 등 다른 선을 쓰면 의미를 범례나 캡션에 표시. 색만으로 정상·장애를 구분하지 않음.
- 화살표는 요청 방향·데이터 흐름·처리 순서 중 무엇인지 설명. 요청과 응답을 구분해야 하면 선에 이름 표시.
- 제목·설명과 Markdown 대체텍스트 포함. 본문에 “그림 1. …”처럼 짧은 캡션과 실제 관측·개념도 여부 표시.
- 넓은 구성도는 원본 그림을 여는 링크와 핵심 관계를 설명하는 본문을 함께 제공. 모바일에서 글자가 작으면 그림을 나누거나 확대해서 읽을 수 있게 구성.
- 사이트 CSS를 바꾸지 않고 그림 파일 내부에서만 배치. 외부 폰트·CDN·스크립트에 의존하지 않음.

## 주의박스·이미지

- 기존 `!!! note "확인"`, `!!! warning "실행 주의"` 양식 사용.
- 적용 범위·위험처럼 독자의 판단에 필요한 내용만 강조. 일반 설명 전체를 박스로 감싸지 않음.
- 이미지는 Markdown 상대 경로로 연결. 대체텍스트에는 핵심 내용, 캡션에는 그림의 의미·근거 수준 표시.
- 화면 증적을 정리할 때는 원본 비율과 읽을 수 있는 글자 크기를 유지. 민감정보가 숨은 레이어나 주석에 남지 않도록 확인.

## 작성 후 확인

검사기와 strict 빌드 후 실제 글 화면 확인. 코드 언어·명령/출력 구분·복사할 내용, 이미지 경로·캡션·한글, PC와 모바일에서 글자 잘림·겹침·페이지 전체 가로 넘침 확인. 빌드 성공만으로 그림의 관계나 실제 결과를 검증했다고 쓰지 않음.
